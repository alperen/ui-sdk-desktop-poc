Rendering, input and memory

At 100 items component calls fell from 15,555 to 11,857 for UI SDK and from 17,500 to 6,141 for Plain React. Update commits stayed at 29 and 38. Plain React’s FileIcon calls fell from 2,112 to 211, ItemLabel from 2,113 to 415 and App.Item from 2,112 to 1,467. Compiled components · Control components.

In Plain React, deep navigation went from 5.885 to 3.145 ms and maximize/restore from 1.255 to 0.115 ms. Some actions took longer. Switching the SDK to columns went from 3.495 to 4.900 ms and opening Photos in Plain React from 2.890 to 3.220 ms. The 1.7% difference for the four-item SDK folder was small relative to round-to-round variation.

Production input processing fell from 71.34 to 64.58 ms for UI SDK and 39.77 to 35.13 ms for Plain React. With compilation enabled, style, layout and paint took 22.78 and 26.11 ms respectively. Open-folder heap after garbage collection went from 6.15 to 6.16 MiB for UI SDK and from 2.84 to 2.73 MiB for Plain React. Both compiled builds reached the first paint opportunity about 16 ms after the double-click. Trace summary · Heap and opening records.

Automatic and manual memoization

At 100 items, compiled UI SDK performed 6,301 block checks (3,233 hits and 3,068 recomputations). Compiled Plain React performed 32,037 (15,341 hits and 16,696 recomputations). Guard evaluation took 0.675 and 3.080 ms, and cache access 0.465 and 0.965 ms, respectively.

UI SDK recorded 8,007 useMemo calls in 2.065 ms, including 6,128 hits and 1,879 factory executions taking 0.240 ms. Its 6,987 useCallback calls took 1.120 ms. Compiled Plain React recorded zero manual calls to either hook. Generated caching replaced the 14 useCallback calls in its control build. Neither build invoked a React.memo comparator. Diagnostic records.

Each generated block condition was evaluated once. Reuse counted as a hit and entering the recomputation branch, including initial population, counted as a miss. Guard timing excludes the work inside the block. Access timing includes useMemoCache. Clock reads affect these small durations. Counters ran separately from the main render measurements and Chrome traces. Instrumentation · Compiler memoization.

Compilation scope and verification

React and React DOM 19.3.1 used babel-plugin-react-compiler 1.0.0 targeting React 19 in infer mode. Both applications’ source trees were compiled. UI SDK 0.1.0-beta.5 and other dependencies ran as published. Compiler setup · Compiling libraries.

The SDK application generated 72 cache blocks and 212 static slots across 14 functions. Plain React generated 115 blocks and 376 slots across 22 functions. Per-file instrumentation counts matched the compiler’s block counts. The compiler skipped SDK Item and Plain React ItemRoot for object mutation, Columns for reading a ref during render and FileList for its nullish assignment. Those functions ran in their original form. Compilation audit.

Chromium 158 and agent-browser 0.43.0 used a 1000 × 700 viewport and the original 4- and 100-item datasets. Each condition received a warm-up. Compiler-off ran first in odd rounds and compiler-on first in even rounds. Both passed 26 checks across 12 interactions. Render totals sum root actualDuration after initial mount. Reproduce the comparison

Start the two servers in separate terminals.

DESKTOP_REACT_COMPILER=0 node benchmarks/serve.mjs
DESKTOP_REACT_COMPILER=1 node benchmarks/serve.mjs

In a third terminal record and summarize both conditions.

node benchmarks/run.mjs /tmp/desktop-compiler-compare all --paired
node benchmarks/summarize.mjs /tmp/desktop-compiler-compare/control
node benchmarks/summarize.mjs /tmp/desktop-compiler-compare

Run the application or its validation gate with DESKTOP_REACT_COMPILER=1 and pnpm dev or pnpm validate. To regenerate the interactive report from the repository’s recorded measurements, run node benchmarks/report.mjs.
